# Smart Aquaculture Monitoring System

## 1. Project Overview

The Smart Aquaculture Monitoring System is designed to monitor important water-quality parameters in aquaculture ponds and fish farms. The system provides a web-based dashboard for displaying water-quality readings, system status, and alerts.

The current implementation uses simulated sensor data generated by a Python Flask backend. The planned hardware integration will use physical water-quality sensors and an ESP32 microcontroller to collect and transmit real-time sensor readings to the backend.

The system aims to help aquaculture farmers identify abnormal water conditions and make informed decisions to maintain a healthy aquatic environment.

## 2. Project Objectives

- Monitor important water-quality parameters, including temperature, pH, dissolved oxygen, turbidity, and ammonia.
- Display water-quality readings and system status through a web dashboard.
- Generate alerts using predefined risk-assessment rules.
- Provide REST API endpoints for communication between the frontend and backend.
- Store and manage sensor readings, alert history, and logs.
- Integrate physical sensors and an ESP32 microcontroller in future development.
- Support future enhancements such as visual graphs and drone-based water monitoring.

## 3. System Architecture

The system is divided into two major parts:

1. **Software System Architecture — Current Implementation**
2. **Hardware System Architecture — Planned / Future Integration**

### 3.1 Software System Architecture

The current software implementation uses simulated data to demonstrate the monitoring system.

#### A. Frontend — Web Dashboard

Technologies:
- HTML
- CSS
- JavaScript

Responsibilities:
- Display water-quality readings.
- Show alerts and system status.
- Automatically refresh displayed data every five seconds.
- Send HTTP requests to the Flask backend.
- Display readings and alerts received as JSON responses.

#### B. Backend — Flask Server

Technologies:
- Python
- Flask

Responsibilities:
- Generate simulated water-quality readings.
- Apply risk-assessment rules to identify abnormal conditions.
- Provide REST API endpoints.
- Process frontend requests.
- Return readings and alerts in JSON format.

Example API endpoint:

`/api/readings`

#### C. Data Layer

The current implementation uses an in-memory data layer.

Responsibilities:
- Store recent simulated readings.
- Maintain temporary alert history.
- Provide data to the backend during application execution.

The current in-memory data layer is temporary. Data may be lost when the application restarts.

### 3.2 Hardware System Architecture

The hardware architecture represents the planned integration of physical sensors and an ESP32 microcontroller.

#### A. Aquaculture Pond / Fish Farm

The system is intended to monitor five water-quality parameters:

- Temperature
- pH
- Dissolved oxygen
- Turbidity
- Ammonia

The sensors collect measurements from the pond and provide signals to the data-acquisition system.

#### B. ESP32 Microcontroller

The ESP32 is planned to collect and process sensor data and transmit it to the backend over Wi-Fi.

Responsibilities:
- Read sensor data through compatible interfaces.
- Process and format sensor readings.
- Transmit data over Wi-Fi using HTTP or HTTPS.
- Support future real-time monitoring integration.

#### C. Internet / Communication Layer

The internet or network connection provides communication between the ESP32 and the backend server.

Communication flow:
1. The ESP32 sends sensor data through an API request.
2. The Flask backend receives and processes the data.
3. The backend applies risk-assessment rules.
4. The backend stores data in the database.
5. The processed data is made available to the frontend.

#### D. Backend Server and Database

The planned hardware-integrated backend will receive physical sensor data instead of relying only on simulated readings.

Responsibilities:
- Receive sensor data from the ESP32.
- Perform risk assessment.
- Store historical readings.
- Maintain alerts and logs.
- Provide REST API endpoints for the dashboard.

A database will be used to maintain historical records and support future analysis.

#### E. Frontend — Hardware-Integrated Dashboard

The dashboard will be extended to support real sensor readings.

Planned features:
- Display live water-quality readings.
- Show alerts and risk status.
- Automatically refresh displayed data.
- Support visual graphs and historical trends in future enhancements.

#### F. Drone — Future Enhancement

Drone-based monitoring is identified as a future enhancement in the architecture.

Potential responsibilities:
- Support water monitoring across larger areas.
- Collect measurements from different pond locations.
- Send monitoring data to the backend.

Drone integration is planned for future development and is not part of the current simulated-data implementation.

## 5. Working Principle

### Current Implementation

1. The user opens the web dashboard.
2. The frontend sends an HTTP request to the Flask backend.
3. The backend generates simulated water-quality readings.
4. Risk-assessment rules are applied to the readings.
5. The backend returns readings and alerts as a JSON response.
6. The frontend displays the results.
7. The dashboard refreshes the information every five seconds.

### Planned Hardware Integration

1. Physical sensors collect water-quality measurements.
2. The ESP32 reads the sensors through compatible interfaces.
3. The ESP32 processes and formats the measurements.
4. The ESP32 sends sensor data to the Flask backend over Wi-Fi.
5. The backend performs risk assessment and stores the readings.
6. The dashboard displays real sensor data, alerts, and system status.

## 6. API Design

The software architecture uses REST API communication between the frontend and backend.

Example endpoint:

`GET /api/readings`

Purpose:
- Retrieve the available water-quality readings from the backend.

The hardware-integrated version will require an appropriate data-submission endpoint for sensor readings from the ESP32.

Example proposed endpoint:

`POST /api/readings`

Purpose:
- Receive sensor readings from the ESP32.

The exact API methods, request formats, and response formats should match the implemented backend.

## 7. Risk Assessment and Alerts

The Flask backend applies risk-assessment rules to available water-quality readings.

The system is intended to:
- Identify readings outside configured thresholds.
- Generate alerts for potentially abnormal water conditions.
- Display alerts and risk status on the dashboard.
- Maintain alert history when persistent storage is implemented.

Thresholds must be validated for the relevant aquatic species and farming conditions before the alerts are used for operational decisions.

## 8. Installation and Execution

### Prerequisites

- Python installed on your computer.
- Flask installed in the Python environment.
- A web browser.
- The project source code.

### Setup

1. Clone or download the project repository.
2. Open the project folder in Visual Studio Code.
3. Create and activate a Python virtual environment if required.
4. Install the dependencies listed in `requirements.txt`, if available.
5. Run the Flask application using the project's configured entry point.
6. Open the local URL displayed in the terminal.
7. View the dashboard and verify that simulated readings and alerts are displayed.

Example installation command:

```bash
pip install flask
```

The exact run command depends on the Flask application's entry-point filename and configuration.
